# Расширенный технический радар

Цель радара - зафиксировать целевой технологический ландшафт на 3 года и показать, какие технологии и архитектурные паттерны следует внедрять, проверять или выводить из критического пути.

Статусы:

- **Adopt** - применять как целевой стандарт.
- **Trial** - внедрять в пилоте или ограниченном домене.
- **Assess** - изучать и готовить решение после проверки применимости.
- **Hold** - не развивать как целевое направление; использовать только как временный мост или выводить из эксплуатации.

| Legacy                 | MS SQL Server 2008 DWH как центр бизнес-логики | Hold   | Не добавлять новую бизнес-логику; оставить только как источник/совместимость на период миграции.                                | Устаревшая версия, дорогая поддержка, долгие отчеты и высокий риск vendor/skills lock-in.                             |
| Legacy                 | PowerBuilder операторский UI                   | Hold   | Не развивать; заменить доменными интерфейсами или оставить только для сценариев, не перенесенных в целевую архитектуру.         | Усиливает зависимость от DWH и редких компетенций.                                                                    |
| Legacy                 | Apache Camel как центральная ESB               | Hold   | Использовать как migration bridge через ACL; новые интеграции строить через события и API.                                      | Camel не должен оставаться бутылочным горлышком при росте доменов и регионов.                                         |
| Legacy                 | Монолитные batch ETL в DWH                     | Hold   | Постепенно декомпозировать в доменные pipelines и потоковые витрины.                                                            | Основная причина многочасовой отчетности и высокой стоимости изменений.                                               |

## Приоритеты внедрения

1. **0-6 месяцев:** Adopt для Terraform/CI/CD, Event Backbone, Schema Registry, Data Contracts, ACL, базового Data Catalog; Trial для Policy-as-Code и SLO data products.
2. **6-18 месяцев:** масштабирование Stream Processing, Lakehouse, Data Governance, Semantic Layer, self-service BI на критичные домены.
3. **18-36 месяцев:** вывод Camel/DWH из критического пути, промышленная эксплуатация Data Mesh, оценка Feature Store и embedded analytics для новых продуктов.
